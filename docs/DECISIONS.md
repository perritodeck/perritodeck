# Decisions

One line per decision, newest last. Format: `YYYY-MM-DD — decision — reason`.

- 2026-10-11 — Project name PerritoDeck; launcher name "Perrito"; ids `dev.perritodeck.*` — bare "Perrito" is unsearchable and its GitHub name is taken; `perritodeck.dev` and the `perritodeck` GitHub org are owned.
- 2026-10-11 — Host in Rust (Tauri 2 for UI later) — small binaries, good cross-platform input/audio crates, same stack as OpenDeck/TilePad so contributors can move between them.
- 2026-10-11 — Android client in Kotlin + Compose, no Google Play Services — F-Droid requires it; old tablets (incl. Fire OS) lack GMS anyway.
- 2026-10-11 — Protocol is JSON over WebSocket with Elgato-style message names — easy to debug, works in browsers, makes an Elgato-SDK shim mostly a rename.
- 2026-10-11 — Golden fixtures instead of codegen for cross-language types in Phase 1 — no extra toolchain; both test suites prove they agree on the wire format.
- 2026-10-11 — Host renders key images; client only displays — mirrors Stream Deck and Companion Satellite, keeps the client trivial and lets one client speak both protocols.
- 2026-10-11 — Phase 1 host binds to 127.0.0.1 by default; LAN requires an explicit flag plus a session token — never allow unauthenticated remote control, even before real pairing exists.
- 2026-10-11 — Default port 46710 — in the dynamic range, no well-known service found on it, and not used by Companion (16622/16623), Macro Deck (8193/8194) or OpenDeck (57116+).
- 2026-10-11 — License: Apache-2.0 for the project, MIT for everything under `plugins/` — permissive for adoption with a patent grant; MIT SDKs let plugin authors use any license. We will not copy code from GPL projects (OpenDeck, StreamController, Stream-Pi).
- 2026-10-11 — Android minSdk 22 (provisional, overrides spec's 26) — test Kindle's Fire OS version unknown; Fire OS 5 is API 22, and old tablets are the core audience. Revisit once known.
- 2026-10-11 — Build independently of TilePad — keep the protocol documented and open so a bridge is easy later.
- 2026-10-11 — AndroidX/Compose pinned to the last releases supporting minSdk 22 (Compose BOM 2025.06.01, core-ktx 1.16) — newer AndroidX raises minSdk to 23. Unpin when minSdk is decided.
- 2026-10-11 — Android uses the framework `Theme.Material` + Compose Material 3, no AppCompat/MDC — fewer dependencies, smaller APK.
- 2026-10-11 — Cleartext `ws://` allowed in Phase 1 (`usesCleartextTraffic`) — hosts are on arbitrary LAN IPs; TLS with a pinned host cert replaces it in Phase 2.
- 2026-10-11 — Gradle wrapper generated by a CI workflow from the official distribution — this dev environment can't reach Gradle's servers, and it guarantees an unmodified wrapper jar.
- 2026-10-11 — Demo grid size uses Android's tablet rule (smallest width ≥ 600dp → 8×5, else 5×3) — matches how Android itself decides tablet layouts.
- 2026-10-11 — A `fakedeck` CLI client ships alongside the host — lets CI and contributors test the host with no Android device.
- 2026-10-11 — Pairing: 6-digit one-time code + TLS with a pinned self-signed host certificate, per-device 256-bit secret (host keeps SHA-256) — no CA or accounts needed; codes are typeable on a tablet; pinning stops LAN impersonation; secrets let devices reconnect silently.
- 2026-10-11 — rustls with the `ring` provider (not aws-lc) — pure Rust + small C, builds on every CI OS without CMake/NASM.
- 2026-10-11 — QR codes open the app via a `perritodeck://pair` link instead of an in-app scanner — any camera app works, no CameraX/ZXing dependency, and most Fire tablets lack a rear camera anyway. In-app scanning can come later.
- 2026-10-11 — Host listens on all interfaces by default from Phase 2 — safe now that pairing and TLS are mandatory, and Wi-Fi works out of the box. `--insecure` (plain ws, no pairing) is loopback-only.
- 2026-10-11 — Phase 1 LAN token removed; `hello.token` stays in the schema as deprecated and ignored.
- 2026-10-11 — Key images rendered with tiny-skia + ab_glyph and a bundled Inter SemiBold (OFL 1.1), sent as lossless PNG — pure Rust, small, deterministic; WebP would need libwebp. PNG of a flat key is a few KB.
- 2026-10-11 — Key pixel size computed on the host from the tablet's reported screen and the client's layout rules (8dp padding/gaps) — images arrive at native resolution, no client-side scaling blur.
- 2026-10-11 — Emulator E2E tests match keys by accessibility label (contentDescription) rather than visible text — works whether a key is drawn as text or as a host-rendered image, and keeps keys screen-reader friendly.
- 2026-10-11 — Wayland input via the RemoteDesktop portal / libei, accepting a permission prompt each time the host starts — no root, no udev rule, works on GNOME and KDE.
- 2026-10-11 — Profiles are TOML files — human-editable with comments; the Phase 3 editor writes the same format.
- 2026-10-11 — "Run command" actions are allowed by default (argv only, no shell) — it's the user's own machine and profile; the Phase 3 UI will make commands visible before saving.
- 2026-10-11 — Vendor enigo 0.6.1 with a two-part patch (portal only on Wayland; errors instead of panics) — upstream would prompt X11 users and crash where no portal exists. To be upstreamed.
- 2026-10-11 — Toggle states belong to the profile, not the device — a "Mic muted" key should look the same on every tablet.
- 2026-10-11 — In-app QR scanning with CameraX + ZXing core — both FOSS, no Play Services; uses the front camera on tablets that only have one; the deep link still works with any camera app.
- 2026-10-11 — OBS and Home Assistant built into the host (not plugins yet) — they're the most-asked integrations and validate the action model before the Phase 5 plugin SDK; settings and secrets live in `integrations.toml`, separate from the shareable profile.
- 2026-10-11 — Home Assistant via REST (`ureq`, rustls/ring) rather than its WebSocket API — one request per press is all actions need; entity state feedback will use the WebSocket API in Phase 4.
- 2026-10-11 — v0.1.0 release and signing deferred by the maintainer; key generated and handed over, secrets not yet set.
- 2026-10-11 — Host runtime moved into the `perritodeck-host` library; the CLI and the desktop app are thin front ends over `Host` — one code path for pairing, profiles and actions.
- 2026-10-11 — Desktop app (`host/app`) is its own Cargo workspace — the headless host and its CI keep building without GTK/WebKit; the app reuses the vendored enigo via its own `[patch.crates-io]`.
- 2026-10-11 — App fonts (Bricolage Grotesque, Atkinson Hyperlegible, OFL) bundled through Fontsource, not loaded from Google Fonts — works offline and sends nothing anywhere.
- 2026-10-11 — The app UI talks to an in-memory mock when opened in a plain browser — Playwright tests and UI work need no Rust build or WebView.
- 2026-10-11 — First app slice shows the profile read-only, with "Edit profile file" — the drag-and-drop editor comes next; live reload already makes hand edits show up in the app and on tablets.
- 2026-10-11 — Test tablet identified: KFMUWI = Fire 7 (2019, 9th gen), 1024×600 mdpi, 1 GB RAM, front and rear 2 MP cameras; launched on Fire OS 6 (API 25), updated to Fire OS 7 (API 28). The `fire7` E2E run already matches its screen. minSdk stays 22 until the hardware check reads the real API level; raising it to 23+ would let AndroidX/Compose be unpinned.
- 2026-10-11 — Several profiles = several TOML files in the profiles folder; the id is the file name. The default profile is the one the host was started with. Which tablet shows which profile, and switching rules, live in `app-settings.json` (machine-specific), not in profiles (shareable).
- 2026-10-11 — Focused-app detection written in-house (Win32 foreground window, macOS CGWindowList owner, X11 `WM_CLASS`) rather than `active-win-pos-rs`, which pulls in a GPL-3.0 crate on Linux. Wayland has no general API; unsupported for now.
- 2026-10-11 — `unsafe_code` lint relaxed from `forbid` to `deny`, allowed only in the focus-detection modules (and one macOS FFI call in the app).
- 2026-10-11 — Profile files keep their comments: the editor changes them with `toml_edit` and checks the whole result before writing atomically. App undo/redo stores file text before/after and refuses to undo over hand edits.
- 2026-10-11 — `.perritoprofile` = zip of `profile.toml` + `images/…`; imports never write outside the profiles folder and always create a new profile.
- 2026-10-11 — CI trimmed to save Actions minutes, which a private repository pays for: pushes run Host tests on Windows only, the desktop UI tests, Android, Protocol, and two emulators (API 22, Fire 7). Linux/macOS host tests, desktop bundles for all three OSes, the real-app test and the other emulators run weekly (Mondays) or by hand. Linux is tested locally before each push, and pushes are batched.
- 2026-10-11 — Sliders are a protocol cell type (`control: "slider"`, gated by the `sliders` capability) rather than a new control layer; older clients just see a key. Values are 0–100; the host coalesces drags and polls levels back every 3 s.
- 2026-10-11 — Live values (`{cpu}`, `{ha:…}`, `{obs:…}`, `{plugin:…}`) are polled every 2 s, and only for names a loaded profile uses. Subscriptions (OBS events, HA WebSocket) can replace polling later without changing profiles.
- 2026-10-11 — USB uses `adb reverse` from the host plus a 127.0.0.1 fallback in the client, instead of a separate USB transport — no new protocol, TLS pinning unchanged, works with any adb-capable tablet.
- 2026-10-11 — Plugins are separate processes speaking JSON lines over stdio (not WebSocket, not in-process): no ports to manage, any language, a crashing plugin can't take the host down. First-party plugins are Python with the standard library only, so they install with no package manager.
- 2026-10-11 — First-party plugins ship inside the desktop app (Tauri resources) and are added from the Plugins page; nothing is downloaded.
- 2026-10-11 — The update check is opt-in (off by default): when on, the app asks the GitHub Releases API once at start and only shows a notice with a link to the release page. No auto-download or install until releases are signed. Port and Wi-Fi access are app settings applied on restart; the command-line host keeps its `--port`/`--listen` flags.
- 2026-10-11 — Animated keys are done on the host: it renders each GIF frame once and sends `setImage` when the frame changes (frames last at least 80 ms; at most 120 frames). No protocol change, so every client animates; the cost is bandwidth, which the frame floor keeps small.
- 2026-10-11 — Online plugin catalogue = a static `index.json` plus zips on the website, each zip pinned by SHA-256 in the index. The app contacts it only when someone presses "Look online", accepts only HTTPS (plain HTTP to loopback for testing), checks the hash, unpacks with path checks, and refuses a zip whose plugin id differs from its catalogue entry. No signing yet; HTTPS on perritodeck.dev is the root of trust.
- 2026-10-11 — Phase 7 (Companion mode, Stream Deck plugins) pulled ahead of Phase 6 packaging, at the maintainer's request.
- 2026-10-11 — Companion mode: the host is a Satellite API client over TCP (simple key grid), one Companion surface per tablet showing a profile with `companion = true`. The deck gets a generic `RemoteSurfaces` hook rather than Companion-specific code, so other remote drawers (e.g. real Stream Deck hardware) can reuse it. Images are passed through as PNG; key up is forwarded only for Companion profiles (PerritoDeck's own keys still act on key down).
- 2026-10-11 — Stream Deck plugin compatibility is a separate host (`perritodeck-sdcompat`) speaking the plugin WebSocket protocol from Elgato's public docs, not a bridge into PerritoDeck's own plugin protocol: plugins need per-key instances that draw their keys, which PerritoDeck plugins don't. The deck gets a generic `KeyAgents` hook. One instance per profile key, shared across tablets. Property inspectors are left for later (settings as JSON). Trademark: the app says "Stream Deck plugin" descriptively; review wording and plugin license terms before release.
- 2026-10-11 — SVG key images (Stream Deck plugins use them a lot) are drawn with resvg (Apache-2.0/MIT), with the bundled Inter font plus system fonts.
- 2026-10-11 — Plugin protocol 1 grows without a version bump (unknown events are ignored): `settings` for a whole plugin (manifest `settings` fields, stored by the host in `plugin-settings/<id>.json`, mode 600 on Unix, sent in `hello` and `settings`), and values with an argument (`{plugin:<id>:<value>:<arg>}`) with a `watch` event listing the arguments profiles use, so plugins fetch only what's shown. Plain values aren't in `watch` (the OBS plugin polls its stats while connected for that reason).
- 2026-10-11 — First-party plugins are Python standard library only, including two hand-written WebSocket clients (OBS obs-websocket 5, TrueNAS JSON-RPC). TrueNAS uses the JSON-RPC WebSocket API because REST is deprecated in 25.04 and removed in 26.04, and refuses plain `http://` because TrueNAS revokes API keys sent unencrypted. All thirteen first-party plugins ship inside the desktop app.
- 2026-10-11 — iOS client: a SwiftPM package (`PerritoKit`, everything testable) plus a thin SwiftUI app generated by XcodeGen (no committed `.xcodeproj`); secrets in the Keychain; iOS CI runs only by hand or weekly. Protocol gains `platform: "ios"`. Building needs a Mac: renting a cloud Mac by the day (a Scaleway Mac mini has a 24-hour minimum, ~€4 for an M2) is the cheapest interactive option; GitHub Actions macOS runners for routine checks once Actions minutes allow it.
- 2026-10-11 — Releases are drafts: a pushed tag builds everything into a draft GitHub Release that a person publishes; the workflow never creates tags and never overwrites a published release. A manual run can build without publishing anything.
- 2026-10-11 — One script (`scripts/release-version.py`) sets and checks the version everywhere (Cargo, lockfiles, Tauri, npm, Android, iOS, download page); the Release workflow refuses a tag that doesn't match or lacks an Android changelog.
- 2026-10-11 — Windows ships both NSIS (per-user, no admin, the default download) and MSI (per-machine, for managed PCs and winget); the MSI upgrade code is pinned. WebView2 via the download bootstrapper. Pre-release versions skip MSI because MSI versions must be numeric.
- 2026-10-11 — macOS minimum 10.15; without Apple secrets the app is ad-hoc signed (`signingIdentity: "-"`) so Apple silicon runs it; signing and notarisation turn on when the secrets exist.
- 2026-10-11 — Linux release builds (CLI and app bundles) run on Ubuntu 22.04 for glibc 2.35 compatibility. Release asset names are stable and versioned (`perritodeck-<v>-<os>-<arch>.<ext>`) so the website can link them directly.
- 2026-10-11 — Flatpak and AUR start as drafts in `packaging/`; F-Droid recipe draft in `docs/fdroid/`. F-Droid first builds and signs itself; reproducible builds (shipping our signature) come after signing is set up.
- 2026-10-11 — Stream Deck property inspectors are shown in an iframe in the app, served by a tiny HTTP server in the Stream Deck host on 127.0.0.1 with a per-start secret in every URL; the bootstrap call (`connectElgatoStreamDeckSocket`) is injected into the page. The plugin socket refuses any `Origin` except that server's. The app's CSP allows `frame-src http://127.0.0.1:*` for this.
- 2026-10-11 — Plugins get a writable folder from the host (`PERRITODECK_PLUGIN_DATA`, under `plugin-data/<id>` in the settings folder) and UTF-8 pipes (`PYTHONUTF8=1`); timer and counter moved their state there.
- 2026-10-11 — Desktop app identifier is `dev.perritodeck.PerritoDeck` (Tauri `identifier`, Flatpak app-id, macOS bundle id). Fixed forever from the first release.
- 2026-10-11 — Two of Stream Deck's built-in actions added. **Random action** is an `ActionSpec` (`{ type = "random", actions = [...] }`): one action picked uniformly per press, validated up front like `multi` (shares its nesting limit, must not be empty), so it can sit inside `multi` and vice versa. **Switch profile** is a navigation, not an action (`nav = { profile = "<id>", page = "<optional>" }`), because it acts on the tablet that was pressed, which actions don't know about. It counts as a manual choice, as on the Tablets page: the assignment is saved in `app-settings.json`. An auto-switch rule matching the app in front doesn't undo it straight away (that would make the key do nothing while, say, OBS is in front); the rules apply again once a different app comes to the front, or after a choice in the app. The target profile and page aren't checked when the profile loads (profiles load on their own), so a missing one flashes ⚠ on press and nothing changes. `NavSpec::Profile` comes before `Page` in the untagged enum, so `{ profile, page }` never reads as a page of this profile, and page renames leave it alone.
- 2026-10-11 — Log files written by the host itself (a small rotating writer in `perritodeck-host::logging`), not `tracing-appender`: no new crates, and rotation by day *and* size. `logs/` in the data folder, `perritodeck.log` plus `perritodeck.1.log` … `.6.log` (seven files of at most 1.4 MB, about 10 MB), owner-only on Unix. Every line written (file and console) passes through a redactor (`Bearer …`, `user:pass@` in URLs, values of fields named like `token`/`password`/`secret`/`api_key`, 32+ hex runs, JWTs), because plugin stderr and URLs can carry secrets. "Detailed logs" (Settings, `detailedLogs` in `app-settings.json`) reloads the filter live to `perritodeck=debug`; `RUST_LOG` still sets the base.
- 2026-10-11 — "Copy diagnostics" / `perritodeck-host diagnostics`: one plain-text report (versions incl. both protocols, paths, tablets with platform and app version, plugins and Stream Deck plugins with state, integrations as set up/reachable only, network, MCP state, last 200 log lines), redacted line by line. The CLI command can't see a running host (no IPC), so it reports what the files say. The app copies with `navigator.clipboard` (falls back to `execCommand`), not a Tauri clipboard plugin.
- 2026-10-11 — The MCP server (`perritodeck-mcp`) is wired into the host: Streamable HTTP on 127.0.0.1 port **46711** (`/mcp`), serving protocol versions 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05 (handshake) and 2026-07-28 (stateless). Off by default, and so are its `press`, `edit` and `run` permissions (`mcp` in `app-settings.json`, read on every request). Reading profiles, tablets and live values is allowed whenever it runs. Giving a key an action that runs programs or plugins needs `run`, not just `edit`, since the key could be pressed later. The bearer token lives in its own owner-only `mcp-token` file, made with `generate_token()`; "Make a new token" restarts the endpoint. The host starts/stops/restarts it on setting changes (`Host::apply_mcp`), in the CLI and the app alike. Assistants that launch a command run `perritodeck-host mcp`, or the desktop app binary with `mcp` (handled in `main` before Tauri starts, because installs ship only the app), which bridges stdio to the running host's endpoint and runs even when it's off so the assistant shows why. A data folder other than the default goes into the snippet as `--data-dir`.
- 2026-10-11 — Assistants press keys by position through `Deck::press_at` (same rules as a tap: toggles share state, followed toggles don't flip, page keys act on the named tablet or every tablet showing the profile, switch-profile keys count as a manual choice, Stream Deck plugin keys need to be on screen). `show_profile` from an assistant also counts as a manual choice, like the switch-profile key.
- 2026-10-11 — Windows fixes from `docs/windows-review-2026-10.md` (written without a Windows build; see the review for what's left). **Launch** retries a program Rust can't find with the PATHEXT names `CreateProcess` runs (`.com/.exe/.bat/.cmd`, so `code` finds `code.cmd`; `.bat`/`.cmd` go through std's safe `cmd.exe` escaping), starts a program given by path in its own folder (Explorer's "Start in"; OBS needs it), and falls back to `ShellExecuteW` for App Paths names, shortcuts and documents. **Command** gets the PATHEXT retry and `CREATE_NO_WINDOW` (output is captured); Launch keeps its console for console programs. `adb` polls also run without a console. `open` uses `ShellExecuteExW` in the CLI too (the app already did through `tauri-plugin-opener`). The pairing link lists the default-route address first (UDP "connect" to 192.0.2.1, nothing sent), so WSL/Hyper-V adapters don't cost a timeout each. **Auto-switch** on Windows keeps the last app when no window is in front or the shell is (taskbar, desktop, Start, Search, Alt+Tab, UAC), and reports the hosted Store app instead of `ApplicationFrameHost`. Python plugins: exit code 9009 within 5 s on Windows (the Store's `python.exe` alias) means "needs Python 3", not a crash. A plugin manifest's `main` may not start with `/` or `\` or contain `:`, on every platform. Each plugin process (both kinds) goes in a Windows **job object** with `KILL_ON_JOB_CLOSE`, so what a plugin starts ends with it; the app stops plugins on `RunEvent::Exit` (Quit) and the CLI on Ctrl+C, waiting up to 3 s. Stream Deck `-info` `platformVersion` is the OS version (`10.0.<build>`, macOS `15.x`). Vendored enigo masks `VkKeyScanExW` to its low byte (shifted keys typed nothing). Media plugin on Windows: 8 s PowerShell timeout, polls every 10 s after 30 s without a media key press (the host can't say whether the value is shown), short error text on keys (also screenshot). Screenshot asks for per-monitor-v2 DPI awareness first. Soundboard on Windows plays in-process through winmm MCI (`mpegvideo`, alias per sound, `setaudio` volume), PowerShell as the fallback. `unsafe_code` is now also allowed in `actions::launch` (`ShellExecuteW`) and `actions::job` (job objects), next to the focus and volume modules.
- 2026-10-12 — Hardware check: the test Fire 7 (KFMUWI, 600×1024) runs Fire OS 7.3.1.7 = Android 9 / **API 28**; Perrito 0.1.0-debug installs and starts on it. minSdk stays 22 for now, at the maintainer's request: raising it and unpinning AndroidX/Compose is its own change, decided separately from the Windows bring-up (one API 28 tablet doesn't rule out Fire OS 5 owners).
- 2026-10-12 — The tablet follows the grid's shape: while the deck shows, Perrito asks for landscape when the grid is wider than tall (the starter 5×3), portrait when taller, and leaves square grids to the tablet (`USER_LANDSCAPE`/`USER_PORTRAIT`, so either way up and the rotation lock's flip are respected). The desktop editor already draws the profile's shape, so the two always match; the host sizes key images for that orientation whichever way the tablet said hello. Chosen by the maintainer over turning the grid for upright tablets (keys would change place) and a per-tablet orientation setting.
- 2026-10-12 — Desktop app: a Tauri command that can wait (for a plugin to stop, or the network) is async and runs through the `blocking` helper; a plain command runs on the UI thread, freezing the window, with no Tokio context (Restart on a Stream Deck plugin aborted the app that way). `SdHost`, like `PluginHost`, keeps the runtime `Handle` so its sync entry points work from any thread. "Restart now" relaunches from the `RunEvent::Exit` handler without `--hidden`, rather than through an environment variable (unsafe to set while threads run on Unix). Logging starts in `setup`, after the single-instance check, so a second launch never writes to or rotates the running app's log.
- 2026-10-12 — USB: forwards are re-checked every poll with `adb -s <serial> reverse --list` and put back when missing (after an adb server restart, a replug or a version-mismatch takeover), rather than a long-lived `adb track-devices` child. Every adb call has a 10 s timeout, `CREATE_NO_WINDOW`, null stdin and adb's own folder as working folder; network serials are still forwarded on purpose. Settings lists only confirmed forwards and says in one line why a tablet isn't connected (serials left out, as the report gets pasted). Background loops skip missed ticks (`MissedTickBehavior::Skip`) instead of catching up after a stall or sleep.
- 2026-10-12 — Launch on Windows: `CREATE_NEW_CONSOLE` for console programs (they get a working window), except a `.bat`/`.cmd` reached by bare name through PATH, which runs hidden: those are mostly editor shims (`code`), and a console tool can still be launched visibly as `cmd /k <tool>`. Whatever `CreateProcess` can't take as a file (URIs, `shell:` paths) and programs needing elevation (740) go to `ShellExecuteW`; no URI allowlist, as Launch already runs arbitrary programs. One pair of surrounding quotes ("Copy as path") is stripped from programs and paths. Command waits for the process (not pipe EOF), captures stderr only, and runs in a job without kill-on-close that is ended only on timeout. OpenPath checks an absolute path exists first (Windows would show a blocking "cannot find" box).
- 2026-10-12 — Auto-switch on Windows: `dwm` and `csrss` (a hung app's "Not Responding" stand-in, system error boxes), Snipping Tool, ShellHost, widgets and the other shell hosts keep the last app; explorer counts as an app only for File Explorer windows; Store frames are recognised by class and an empty frame is no app; processes that can't be opened are named from the process list; rules match ignoring case, spaces and a trailing `.exe`. With no app in front, the last app counts as gone (the default profile comes back) once its process quits or its window closes or hides with no other window to go back to. The per-look decision is a tested `focus::Watch`.
- 2026-10-12 — Plugin processes: plugin job objects allow explicit breakaway only (`KILL_ON_JOB_CLOSE | BREAKAWAY_OK`, never silent): a plugin's own children end with it, and a program meant for the user leaves the job by being started with `CREATE_BREAKAWAY_FROM_JOB`. Python SDK 1.3.0 adds `open_for_user` and `start_for_user` for that, and plugins must use them rather than `webbrowser`, `os.startfile` or `subprocess` for browsers and apps that should outlive them; such programs start in their own folder or the home folder, never the plugin folder. On Windows the host runs Python plugins with the interpreter `py -3` (or `python`) reports, cached, instead of `py -3 main.py`, so `py.exe`'s silent-breakaway job isn't in the chain; no working Python 3 path means "needs Python 3" (replaces the 9009 check). Plugins start suspended and are resumed only once in their job, and count as exited only when the job is empty.
- 2026-10-12 — Input on Windows: the text action types one character per `SendInput`, 15 ms apart, because Windows 11 Notepad drops and repeats characters that arrive less than about 10 ms apart (measured; about 1.5 s per 100 characters). Hotkeys hold the main key 50 ms (OBS polls key state every 25 ms). Letters and digits go by virtual key on every layout; other characters get the Shift/AltGr their layout needs, except Shift for `+` so `ctrl+plus` stays the zoom-in =/+ key. Win+L calls `LockWorkStation`. Record saves printable keys by `KeyboardEvent.key`. Vendored enigo types `\n`, `\r`, `\r\n` and `\t` only as Return/Tab keys and sends extended keys with the extended flag (both in `vendor/enigo/PERRITODECK.md`).
- 2026-10-12 — Pairing: Perrito tries 127.0.0.1 first, for QR pairing (in parallel with the link's addresses) and every reconnect; the certificate pin keeps anything else there from being accepted, and a mismatch on 127.0.0.1 isn't fatal while other addresses remain (the cable may lead to another computer). Pairing over the cable saves the network address for later. The host lists 127.0.0.1 last in pairing links when adb is found, reads its addresses fresh on every call, leaves out link-local ones, and advertises IPv4 only over mDNS (it listens on 0.0.0.0). Diagnostics say whether Windows classes the network Public or Private (PowerShell `Get-NetConnectionProfile`, only when a report is made). Connection failures are explained in plain words on the tablet, not as exception text.
- 2026-10-12 — MCP: the Claude Code command is `claude mcp add --scope user perritodeck "--" "<exe>" mcp` (user scope works in every folder; the quoted `--` survives Windows PowerShell's npm shim; any argument with a backslash is quoted for bash). The stdio bridge looks the endpoint up again after a refused connection or a 401, so a new token or port doesn't need an assistant restart, and never resends a message the host may have acted on. The bridge stays the app exe for now (a connected assistant locks it); a separate console `perritodeck-mcp.exe` is the follow-up. Log rotation moves files only into a free number and backs off for 60 s if the current file is held open by another program.
- 2026-10-12 — Text actions are limited to 2,000 characters (Unicode scalar values), checked wherever actions are validated, so a profile holding a longer one doesn't load and the editor's field stops there: at the Windows pace of 15 ms per character the longest wait is 30 s, during which the keyboard is held for all other input and can't be cancelled. All input work runs off the async workers (`EnigoInput::with` → `blocking`). Record keeps the shifted character on Windows and macOS (their backends find the key on any layout) but saves Shift plus the unshifted US key on Linux, whose X11 backend only searches the unshifted level.
