# Decisions

One line per decision, newest last. Format: `YYYY-MM-DD — decision — reason`.

- 2026-10-11 — Project name PerritoDeck; launcher name "Perrito"; ids `dev.perritodeck.*` — bare "Perrito" is unsearchable and its GitHub name is taken; `perritodeck.dev` and the `perritodeck` GitHub org are owned.
- 2026-10-11 — Host in Rust (Tauri 2 for UI later) — small binaries, good cross-platform input/audio crates, same stack as OpenDeck/TilePad so contributors can move between them.
- 2026-10-11 — Android client in Kotlin + Compose, no Google Play Services — F-Droid requires it; old tablets (incl. Fire OS) lack GMS anyway.
- 2026-10-11 — Protocol is JSON over WebSocket with Elgato-style message names — easy to debug, works in browsers, makes an Elgato-SDK shim mostly a rename.
- 2026-10-11 — Golden fixtures instead of codegen for cross-language types in Phase 1 — no extra toolchain; both test suites prove they agree on the wire format.
- 2026-10-11 — Host renders key images; client only displays — mirrors Stream Deck and Companion Satellite, keeps the client trivial and lets one client speak both protocols.
- 2026-10-11 — Phase 1 host binds to 127.0.0.1 by default; LAN requires an explicit flag plus a session token — never allow unauthenticated remote control, even before real pairing exists.
- 2026-10-11 — Default port 46710 — in the dynamic range, no well-known service found on it, and not used by Companion (16622/16623), Macro Deck (8193/8194) or OpenDeck (57116+).
- 2026-10-11 — License: Apache-2.0 for the project, MIT for everything under `plugins/` — permissive for adoption with a patent grant; MIT SDKs let plugin authors use any license. We will not copy code from GPL projects (OpenDeck, StreamController, Stream-Pi).
- 2026-10-11 — Android minSdk 22 (provisional, overrides spec's 26) — test Kindle's Fire OS version unknown; Fire OS 5 is API 22, and old tablets are the core audience. Revisit once known.
- 2026-10-11 — Build independently of TilePad — keep the protocol documented and open so a bridge is easy later.
- 2026-10-11 — AndroidX/Compose pinned to the last releases supporting minSdk 22 (Compose BOM 2025.06.01, core-ktx 1.16) — newer AndroidX raises minSdk to 23. Unpin when minSdk is decided.
- 2026-10-11 — Android uses the framework `Theme.Material` + Compose Material 3, no AppCompat/MDC — fewer dependencies, smaller APK.
- 2026-10-11 — Cleartext `ws://` allowed in Phase 1 (`usesCleartextTraffic`) — hosts are on arbitrary LAN IPs; TLS with a pinned host cert replaces it in Phase 2.
- 2026-10-11 — Gradle wrapper generated by a CI workflow from the official distribution — this dev environment can't reach Gradle's servers, and it guarantees an unmodified wrapper jar.
- 2026-10-11 — Demo grid size uses Android's tablet rule (smallest width ≥ 600dp → 8×5, else 5×3) — matches how Android itself decides tablet layouts.
- 2026-10-11 — A `fakedeck` CLI client ships alongside the host — lets CI and contributors test the host with no Android device.
- 2026-10-11 — Pairing: 6-digit one-time code + TLS with a pinned self-signed host certificate, per-device 256-bit secret (host keeps SHA-256) — no CA or accounts needed; codes are typeable on a tablet; pinning stops LAN impersonation; secrets let devices reconnect silently.
- 2026-10-11 — rustls with the `ring` provider (not aws-lc) — pure Rust + small C, builds on every CI OS without CMake/NASM.
- 2026-10-11 — QR codes open the app via a `perritodeck://pair` link instead of an in-app scanner — any camera app works, no CameraX/ZXing dependency, and most Fire tablets lack a rear camera anyway. In-app scanning can come later.
- 2026-10-11 — Host listens on all interfaces by default from Phase 2 — safe now that pairing and TLS are mandatory, and Wi-Fi works out of the box. `--insecure` (plain ws, no pairing) is loopback-only.
- 2026-10-11 — Phase 1 LAN token removed; `hello.token` stays in the schema as deprecated and ignored.
- 2026-10-11 — Key images rendered with tiny-skia + ab_glyph and a bundled Inter SemiBold (OFL 1.1), sent as lossless PNG — pure Rust, small, deterministic; WebP would need libwebp. PNG of a flat key is a few KB.
- 2026-10-11 — Key pixel size computed on the host from the tablet's reported screen and the client's layout rules (8dp padding/gaps) — images arrive at native resolution, no client-side scaling blur.
- 2026-10-11 — Emulator E2E tests match keys by accessibility label (contentDescription) rather than visible text — works whether a key is drawn as text or as a host-rendered image, and keeps keys screen-reader friendly.
