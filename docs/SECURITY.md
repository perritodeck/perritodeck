# Security

PerritoDeck's host can type keystrokes and run programs on your computer, so anything that can talk to it is effectively a keyboard. This file is the threat model and review checklist; it grows with each phase. How to report a problem is in [SECURITY.md](../SECURITY.md).

## Threat model

| Threat | Today | Planned |
|---|---|---|
| Someone on the same Wi-Fi drives your computer | Every device must pair with a one-time 6-digit code (5-minute window, single use, burned after 5 wrong guesses). Each device gets its own 256-bit secret; the host stores only its hash; `revoke` disconnects and forgets a device | Approve-on-host prompt for new devices (Phase 3 UI) |
| Traffic sniffed or altered on Wi-Fi | TLS (rustls, TLS 1.2/1.3) with the host's self-signed certificate pinned by SHA-256 on the client | — |
| Someone impersonates the host during pairing | QR link carries the fingerprint; typed codes show a fingerprint to compare by eye | — |
| Malicious web page in your browser connects to the host | WebSocket upgrades with an `Origin` header are refused; pairing is required anyway | — |
| Host key theft from disk | Private key and device list written with owner-only permissions (Unix); Windows relies on the per-user profile ACL | OS keychain storage (Phase 6) |
| Oversized or malformed frames | 64 KiB message limit; malformed frames rejected with `badMessage`; handshake timeout; idle timeout | Rate limiting |
| Plugins doing more than they claim | Plugins run as the user, with no sandbox; the app says so when adding them. Their settings (tokens) are stored owner-only (`plugin-settings/`, `sdplugins/settings.json`) and never logged by first-party plugins. Plugins that sign in to a service or pair with a device keep their tokens or keys in files in their own data folder, `plugin-data/<id>/`, and write those files owner-only (the folder itself isn't; on Windows, the per-user profile ACL applies): Twitch and Spotify keep OAuth tokens in `tokens.json`, and Hue keeps the bridge's application key in `hue.json`, which gives full control of the lights from the local network. Owner-only keeps out other accounts, not other programs you run: anything running as you can read these files, like the rest of the data folder | Declared permissions shown at install; signing |
| Tampered plugin download | Online catalogue: HTTPS only, size and file-count caps, zip paths checked, SHA-256 must match the index, plugin id must match its entry. The hash comes from the same server as the zip, so it guards against corruption, not a compromised perritodeck.dev | Signed index |
| Web page or other local program poses as a Stream Deck plugin | The plugin WebSocket listens on 127.0.0.1 only and refuses upgrades with an `Origin` header (browsers always send one). Another program running as the same user could still connect while a plugin isn't | Per-launch tokens |
| Plugin images (SVG) reading local files | SVG `<image>` may only use `data:` URLs; images are scaled to at most 288 px | — |
| Rogue or spoofed Companion on the LAN | Lines capped at 4 MB; silent connections dropped after 10 s; Companion only draws keys and receives presses of tablets showing a Companion profile | — |
| AI assistant (MCP) or another local program drives the host | Off by default. Listens on 127.0.0.1 only (refuses other addresses); every request needs a 256-bit bearer token (constant-time compare) kept in an owner-only `mcp-token` file; `Host` must be the loopback address and port and any `Origin` a localhost page (DNS rebinding); bodies capped at 1 MB; tool calls rate-limited. Pressing, editing and running are separate permissions, all off by default; keys that run programs or plugins, or type text and press Enter, need `run` (the same keys an import lists). **Read tools are always on while it runs and expose key settings** (commands, URLs, text a key types), so don't keep secrets in key actions | Per-assistant tokens; approve-on-host prompt |
| Strangers on a public network reach the host | Pairing and TLS are required whatever the network. The installers add no firewall rule (maintainer's decision, 2026-10-12): Windows asks on first run, and on a network it calls Public its default answer keeps tablets out. Opening Public networks is left to the person; the app only explains how, on the Tablets and Pair pages, when Windows Firewall has no rule for it. It reads the firewall's rules and never changes them | — |
| Someone swaps the bridge program assistants start | Assistants start `perritodeck-mcp` from `bin/` in the data folder, a copy the app makes at start. That folder is writable by the user, which is the same trust level as the rest of the data folder: whoever can write there can already change profiles (keys that run commands) and plugins, so the copy adds no new way in. The app replaces a copy that differs from the one it ships, at every start | Check the copy's signature once releases are signed |
| Someone shares a profile with keys that run programs | Importing a `.perritoprofile` lists every key that runs a program, opens a file, uses a plugin (installed or not), or types text and presses Enter (text with a line break, or text in a key that also presses Enter, Ctrl+M or Ctrl+J): on every page, reachable or not, in every toggle state, inside several-step and random keys, and sliders that run a program or plugin. Each shows the whole command, every argument on its own, with line breaks, tabs, control characters and invisible or direction-changing characters marked rather than shown. Nothing is written, images included, until the person picks **Import with these keys off** (what's listed is removed; the keys keep their look, and toggles their other states), **Import everything**, or Cancel; a profile with no such keys is added at once. The list comes from what the file contains, never from what it says about itself, so older exports are checked too, and what's written is the very text that was checked. An import writes only the profile and the images its keys show (png, gif, jpg or jpeg, inside the profiles folder; at most 5,000 entries, 20 MB each, 100 MB in all), so it can't add another profile, a plugin or settings. Not listed: live values in titles and `follow` (`{plugin:…:…:argument}`) make an installed plugin look up its argument as soon as the profile is loaded, before any press, and the first-party uptime plugin connects to the address it names, even after **Import with these keys off**. Profiles copied into the profiles folder by hand aren't checked; see the bridge row | Plugins mark which value arguments are addresses, and imports list those |
| Secrets in logs and bug reports | Log files owner-only; every logged line is redacted (bearer tokens, URL passwords, `token=`/`password:`-style values, long hex, JWTs); diagnostics leave out keys, certificates, tokens and integration addresses | — |
| Command injection via action settings | Command and launch actions take an argv array and never run through a shell; URLs limited to http/https/mailto. Imported profiles list such keys before adding them (see the sharing row) | — |

## Review checklist (every PR touching host networking or actions)

- [ ] No new listener binds beyond loopback without authentication.
- [ ] Secrets compared in constant time; never logged.
- [ ] Every client-supplied size/index is bounds-checked.
- [ ] No shell interpolation of user or plugin data.
- [ ] New protocol messages are in the schema with `additionalProperties: false`.
- [ ] A new action or slider type is sorted in `ActionSpec::runs_programs` / `SliderSpec::runs_programs` (no catch-all arm), and in `perritodeck_profile::risk` if it types or presses keys.
- [ ] Anything that reads a `.perritoprofile` goes through `Host::stage_import`.

## Reporting

Don't open a public issue, discussion or pull request for a security problem. Report it privately, as [SECURITY.md](../SECURITY.md) describes: through GitHub's private vulnerability reporting (the **Report a vulnerability** button on the repository's Security tab), or by email to [dev@perritodeck.dev](mailto:dev@perritodeck.dev) with "SECURITY" in the subject. SECURITY.md also covers response times, supported versions and what's in scope.
