# The website (perritodeck.dev)

The source is in [`website/`](../website/). Cloudflare publishes every file in that folder,
so notes about the site live here instead: this file used to be `website/README.md`, which
was live at `https://perritodeck.dev/README.md`. File names in the first sections are in
`website/`, except `plugins/build_catalog.py`, `plugins/test_build_catalog.py` and those
starting with `docs/`, `host/` or `scripts/`.

Plain HTML and CSS, no build step, no framework and no third-party requests. JavaScript is
used only where it adds something: the demo deck on the home page (`deck.js`), the download
page picking out your system (`download.js`), and the plugin catalogue's search box
(`catalogue.js`). Every page works without it.

| Page | What |
|---|---|
| `index.html` | Home: what it is, the three use cases, how it works, the demo deck, where it stands |
| `features.html` | What it does, with app screenshots |
| `compatibility.html` | Stream Deck plugins and Bitfocus Companion: what works and what doesn't yet |
| `faq.html` | Questions people ask before trying it |
| `download.html` | Downloads, requirements, checking a download, building from source. Its version is updated by `scripts/release-version.py` |
| `privacy.html` | The privacy policy the store listings link to. Keep it matching what the apps do |
| `guide/` | The user guide. It changes in the same commits as the features it describes |
| `plugins/` | Generated by the top-level `plugins/build_catalog.py` (not committed): the catalogue page, `index.json` for the app, and one zip per plugin. The page's style and script are the committed `catalogue.css` and `catalogue.js` |
| `404.html` | What Cloudflare shows, with a 404 status, for any address that doesn't exist |
| `_headers` | Response headers: the Content-Security-Policy and friends (see [Headers](#headers-_headers)) |
| `robots.txt`, `sitemap.xml` | For search engines. Add new pages to the sitemap |

Every page shares the header and footer markup; copy them from an existing page when adding
one, and mark the current section with `aria-current="page"`. `404.html` is the exception:
it can be served at any depth, so its links start with `/`.

Every page's `<head>` also has a canonical link and the tags link previews use (Open Graph
and `twitter:card`): the page's own address on `https://perritodeck.dev` without `.html`
(folders end in `/`), the same title and description as the page, and the preview image
`https://perritodeck.dev/img/og.png`. Copy them too when adding a page, change the address,
title and description, and add the address to `sitemap.xml`. `404.html` has none, because
it answers at any address. The catalogue page's `<head>` is in the template in
`plugins/build_catalog.py`.

**No inline code.** The site's Content-Security-Policy allows only files from the site
itself, so a `<script>` without `src`, a `<style>` block, a `style="…"` attribute or an
`onclick` would silently stop working once deployed. Put scripts in a `.js` file and styles
in `style.css`, `guide/guide.css`, `download.css` or `catalogue.css`. The same goes for the
catalogue template in `plugins/build_catalog.py`. `plugins/test_build_catalog.py` checks
every page, that each script, stylesheet and image a page loads exists, and that the
stylesheets' `url(…)` and `@import` point only at files in `website/` (no `data:` URIs, no other
sites). It also checks that each page's canonical link, link-preview tags and
`sitemap.xml` entry agree, and that the preview image exists at the size the tags give.

**Only files the site serves.** `website/` holds pages, stylesheets, scripts, images, fonts
with their licence files, `_headers`, `robots.txt` and `sitemap.xml`. Notes go in this file
and scripts in `scripts/`, because anything else in `website/` would be published too. The
same test fails on any other kind of file there (it skips the generated `plugins/`); if the
site needs a new kind of file, add it to the test's list.

## Fonts and images

- `fonts/`: Bricolage Grotesque (variable, weight and optical size) and Atkinson Hyperlegible
  (regular and bold), latin subsets from the Fontsource packages, under the SIL Open Font
  License (licence files alongside). `style.css` declares them.
- `img/`: WebP made from the PNG masters with Pillow at quality 90, alpha kept. The masters
  are in `docs/assets/site/` (the device mockups, scaled to 1400 or 1100 px wide) and
  `docs/assets/screenshot-*.png` (the app, light and `-dark`, scaled to 1600 px into
  `img/app/`). Pages show the dark screenshots with `<picture>` when the system is dark.
- `paw.svg` is `docs/assets/icon-master-rounded.svg`, the app icon. `favicon.ico` (16, 32 and
  48 px, for browsers that don't use the SVG) is `docs/assets/icon-rounded-1024.png`
  scaled with Pillow. `apple-touch-icon.png` (180 px) is the square `icon-1024.png` instead,
  because iOS rounds the corners itself and turns transparent ones black.
- `img/og.png` (1200 × 630) is the picture link previews show, named by every page's
  `og:image`. It's a PNG because every service that shows link previews accepts PNG and
  JPEG, while WebP isn't safe everywhere. Keep it under about 300 KB, since some chat apps
  skip larger previews (it's about 220 KB). [`scripts/og-image.py`](../scripts/og-image.py)
  makes it with Pillow: on the light theme's `--fog` with a soft `--apricot` glow,
  `docs/assets/site/devices-hero.png` scaled to 700 px wide on the right, and on the left
  `docs/assets/icon-rounded-1024.png` at 72 px, the name, the home page's tagline, "Free and
  open source. No account, no cloud." and `perritodeck.dev` in `--apricot-deep`. The text is
  Inter SemiBold (`host/crates/render/assets/Inter-SemiBold.otf`, SIL Open Font License),
  because Pillow can't read the site's woff2 fonts. Remake it with
  `python3 scripts/og-image.py` (`py -3` on Windows) when the hero picture, the icon or the
  tagline changes. With the same Pillow it writes the same bytes, so a run with nothing
  changed leaves git clean.

Quality bar: works at phone width (375 px) and wide (1440 px), in light and dark, with
visible keyboard focus, and each page under about 200 KB before images.

## Preview

```sh
cd website && python3 -m http.server 8000   # then open http://localhost:8000
python3 plugins/build_catalog.py website/plugins   # to preview the plugin catalogue too
```

`http.server` doesn't send the headers in `_headers`, so the Content-Security-Policy only
applies once deployed. `python3 -m unittest test_build_catalog` in `plugins/` catches inline
code before then, and CI runs it (the Plugins workflow) on every change under `website/`.

## Deploy

**Cloudflare Pages** with **Git integration**: free, works while the repository is private,
and redeploys on every push to `main`. Don't use Direct Upload: a Direct Upload project can
never be connected to Git later. The canonical address is the bare domain,
`https://perritodeck.dev` (no `www`), which is what the app's catalogue URL
(`https://perritodeck.dev/plugins/index.json`) and every link in the repository use.

### Where it stands

Checked 2026-10-15 from outside: DNS by asking Cloudflare's nameservers (`aida` and
`algin.ns.cloudflare.com`) and the `.dev` registry directly, and HTTP with `curl -sI`.

- The domain is on Cloudflare's Free plan, and `https://perritodeck.dev` serves `main`:
  every response carries the policy from `_headers` and the temporary
  `X-Robots-Tag: noindex`, `/plugins/index.json` answers with the catalogue (also to the
  app's `PerritoDeck` user agent), and `http://` redirects to `https://`. So the custom
  domain is attached, and the registrar's leftover apex record no longer gets in the way.
  `/README.md` still answers 200 with the old copy of this file until the commit that
  moved it here is deployed.
- The pages carry nothing Cloudflare injects (no `/cdn-cgi/` scripts, so no Web Analytics
  beacon, Rocket Loader or Email Address Obfuscation) and no `Speculation-Rules` header
  from Speed Brain.
- `www` has a proxied record but no redirect, so it answers 522.
- Mail: the `MX` records point at ImprovMX, and both `TXT` records exist: SPF
  (`v=spf1 include:spf.improvmx.com ~all`) and `_dmarc` (`v=DMARC1; p=none`, with reports
  going to Cloudflare's DMARC Management). Which service to keep is D2 in
  [`plan/phase-8.md`](plan/phase-8.md).
- DNSSEC is switched on at Cloudflare (the zone serves `DNSKEY` records), but the `.dev`
  registry has no `DS` record for the domain yet, so it isn't in force.
- Two zone settings add headers that have to go ([The domain](#the-domain), step 1):
  `Strict-Transport-Security: max-age=0`, from Cloudflare's own HSTS setting, which
  replaces the two-year header in `_headers`; and `Nel` and `Report-To`, from Network Error
  Logging.
- The live project doesn't behave like a Pages project. `perritodeck.pages.dev` doesn't
  exist (Cloudflare's own `pages.dev` nameservers answer NXDOMAIN); `/privacy.html` and
  `/index.html` redirect with a 307 where Pages sends a 308; responses lack the
  `Access-Control-Allow-Origin: *` and `X-Content-Type-Options: nosniff` that Pages adds to
  everything; and `/nope` answers 404 with an empty body instead of `404.html`, which is
  deployed (`/404` serves it with a 200). A Worker with static assets behaves like that,
  and **Workers & Pages → Create** can make either kind from a Git repository. See the next
  section.

### The project

**Check first which kind the live one is:** Workers & Pages → the project. A Pages project
has a `*.pages.dev` address, a Worker a `*.workers.dev` one (or none, if that's turned
off). If it's a Worker, the maintainer chooses (the 2026-10-13 decision in
[`DECISIONS.md`](DECISIONS.md) says Pages):

- **Pages, as decided:** create the Pages project below and check its `*.pages.dev`
  address. Then move the domain: remove `perritodeck.dev` from the Worker (**Settings →
  Domains & Routes**) and add it to the Pages project (**Custom domains → Set up a custom
  domain**, and let Cloudflare create the record; a hand-made one gives a 522). The site is
  down for the few minutes in between. Delete the Worker afterwards.
- **Keep the Worker:** commit a Wrangler config at the repository root that publishes
  `website` as static assets with `"not_found_handling": "404-page"`, add
  `X-Content-Type-Options: nosniff` to the `/*` rule in `_headers`, turn off the
  `workers.dev` address and preview URLs (**Settings → Domains & Routes**), and record the
  change in `DECISIONS.md`. The `pages.dev` parts of this file don't apply then.

Creating the Pages project:

1. Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git** (it may say
   "Import an existing Git repository") → GitHub. Sign in to GitHub as an owner of the
   perritodeck organization, install "Cloudflare Workers and Pages" on it with **Only select
   repositories**, and pick `perritodeck/perritodeck`.
2. Settings:

   | Field | Value |
   |---|---|
   | Project name | `perritodeck` (if Cloudflare adds a suffix, use the real `*.pages.dev` name below) |
   | Production branch | `main` |
   | Framework preset | **None** |
   | Build command | `python3 plugins/build_catalog.py website/plugins` |
   | Build output directory | `website` |
   | Root directory (advanced) | leave it blank: the build needs the repository root to reach `plugins/` |
   | Environment variables | none needed. Optionally `PYTHON_VERSION` = `3.12`, to match the plugin tests in CI |

   There's no `package.json` or `requirements.txt` at the root, so nothing is installed and
   the build takes seconds. If the log says `python3: not found`, use `python` instead.
3. **Save and Deploy.** The log lists 24 zips, then `24 plugin(s) in website/plugins/index.json
   and index.html`. Check `https://perritodeck.pages.dev/plugins/index.json`.
4. **Settings → Builds & deployments:**
   - **Preview branches → Custom**: include `*`, exclude `ci/*` and `dependabot/*` (or choose
     **None**). CI no longer pushes branches (E2E screenshots are workflow artifacts now),
     but keep `ci/*` excluded in case a bot branch comes back: each push to one would use
     one of the 500 free builds a month, and fail.
   - **Build watch paths**: include `website/*` and `plugins/*`, exclude nothing. A push that
     touches neither doesn't rebuild the site.
   - Leave production deploys on, and **Web Analytics** off (the privacy policy says the site
     has no analytics).
   - Preview deployments get `X-Robots-Tag: noindex` from Cloudflare automatically.

### The domain

Done: the nameservers, the custom domain, and the SPF and DMARC records. Left:

1. **Zone settings, now** (the site is already live):
   - SSL/TLS **Full (strict)**, **Always Use HTTPS** on (it is: `http://` gets a 301),
     minimum TLS 1.2. Every `.dev` domain is already on the browsers' HSTS preload list.
   - **HTTP Strict Transport Security** (SSL/TLS → Edge Certificates): turn **Enable HSTS**
     off completely. Choosing Max Age "0 (Disable)" doesn't turn it off: it still sends
     `max-age=0`, which is what the site answers with now, and Cloudflare's header replaces
     the one in `_headers` (two years, `includeSubDomains`, `preload`). The site sets HSTS
     in one place, `_headers`.
   - **Network Error Logging** (NEL, under Network) **off now**: while it's on, every
     response carries `Nel` and `Report-To`, and visitors' browsers send reports about
     failed page loads to Cloudflare, which the privacy policy doesn't mention. If the
     dashboard has no switch for it, the API's zone setting `nel` does the same
     (`{"value": {"enabled": false}}`).
   - Turn **off** Web Analytics / RUM (it's on for free zones by default outside the EU),
     **Email Address Obfuscation** (it rewrites the `mailto:` link and injects a script),
     **Rocket Loader**, **Bot Fight Mode** (it can challenge the app's `PerritoDeck` user
     agent, and Look online then fails with "answered 403"), and **Speed Brain** (Speed →
     Optimization: it has browsers fetch pages before the visitor opens them).
   - Caching → **Browser Cache TTL: Respect Existing Headers**, so `_headers` decides.
2. **`www`: a redirect, not a record.** `www` already has a proxied record, which is all a
   redirect needs, so don't add another. Add a **Bulk Redirect** list sending
   `www.perritodeck.dev` (include subdomains on) to `https://perritodeck.dev` with a 301,
   keeping the path and query string, and create the Bulk Redirect rule that uses the list.
   With a Pages project, add its `*.pages.dev` address to the same list with include
   subdomains **off**, so `<hash>.<project>.pages.dev` previews keep working. (A Redirect
   Rule in the zone would do for `www` alone, but can't match the `pages.dev` address,
   which isn't in the zone.) If the `www` record ever goes, recreate it as a proxied `A`
   record to `192.0.2.1`: that address is reserved for examples and never answers; the
   record only gives Cloudflare a name to put the redirect on.
3. **DNSSEC: only the DS record at the registrar is left.** DNS → Settings shows it (key
   tag, algorithm, digest type and digest); add it in the registrar's DNSSEC settings.
   DNSSEC is in force once Cloudflare sees it there, which that settings page shows, and
   `dig +short DS perritodeck.dev @1.1.1.1` (Windows:
   `Resolve-DnsName perritodeck.dev -Type DS -Server 1.1.1.1`) prints it. If the domain
   ever moves away from Cloudflare's nameservers, remove the DS record at the registrar
   first, or the domain stops working.
4. **Mail for `dev@` (D2, the maintainer's decision).** SPF and DMARC are in place: don't
   add them again. A domain has only one SPF record, and two make both fail. Keeping
   ImprovMX needs nothing more in DNS. If Cloudflare Email Routing replaces it, delete
   ImprovMX's `MX` records and edit the existing SPF record to what Email Routing asks for,
   rather than adding one; `_dmarc` stays. Then send a test mail to `dev@perritodeck.dev`
   from an outside address. Both services only receive and forward: answering as `dev@`
   without showing a personal address needs a sending service as well (ImprovMX's paid
   SMTP, another relay, or a hosted mailbox), and that service's own SPF and DKIM entries.
5. The privacy policy's address is `https://perritodeck.dev/privacy` (`/privacy.html`
   redirects there). That's the one for Play Console's privacy policy field and the other
   store listings, and Play's closed test needs it to load.

### Headers (`_headers`)

- Rules match the request path, and pages are served without `.html` (`/features`), so
  rules use `/*`, not `/*.html`.
- There's **one** `Content-Security-Policy`, on `/*`. When two rules set the same header on
  a path, they're joined with a comma, which for CSP means two policies that must both
  pass. Add to the existing line rather than adding a rule.
- The policy allows scripts, styles, fonts and images from the site itself and nothing else:
  no inline code (see the top of this file), no other sites, no `fetch`. Anything from
  elsewhere, such as a web font service, an embed or analytics, is blocked until the policy
  says otherwise, and then `privacy.html` needs updating too.
- Also sent: HSTS (two years, `includeSubDomains`, `preload`, as long as Cloudflare's own
  HSTS setting is off), `Referrer-Policy: no-referrer`, a `Permissions-Policy` that turns
  off the camera, microphone, location, payments and USB, `Cross-Origin-Opener-Policy` and
  `X-Frame-Options: DENY`. Keep Permissions-Policy to feature names Chrome knows; an unknown
  one logs a console error.
- `X-Robots-Tag: noindex` on `/*` is **temporary**, to keep search engines out until launch.
  The `*.pages.dev` address keeps its own noindex rule for good.
- Caching: `/fonts/*` for a year (rename a font file if it ever changes), `/img/*` for a day.
  HTML pages, `style.css`, the scripts and `/plugins/` keep the default, which checks for a new
  version on every visit: their names don't change between versions, and `index.json` must
  always match the zips next to it.
- Pages adds `X-Content-Type-Options: nosniff` and `Access-Control-Allow-Origin: *` itself.
  A Worker doesn't, and the live site doesn't get them today (see
  [Where it stands](#where-it-stands)).
- Without `404.html`, Pages would treat the site as a single-page app and answer every
  unknown address with the home page and a 200. A Worker serves `404.html` only with
  `"not_found_handling": "404-page"` in its config.

**Checks after the deploy**, for a POSIX shell (on Windows, Git Bash runs them as they
are). In PowerShell, type `curl.exe` (in Windows PowerShell `curl` is `Invoke-WebRequest`),
`Select-String` for `grep -i -E` (it ignores case by default) and `NUL` for `/dev/null`.

```sh
curl -sI https://perritodeck.dev/ | grep -i -E '^(strict-transport-security|nel|report-to|x-robots-tag):'
```

This prints exactly one line, `strict-transport-security: max-age=63072000;
includeSubDomains; preload`: no `max-age=0`, no `Nel` or `Report-To`, and no
`X-Robots-Tag` once the noindex line is gone.

```sh
curl -sI https://www.perritodeck.dev/download         # 301, location: https://perritodeck.dev/download
curl -sI https://perritodeck.dev/plugins/index.json   # 200, content-type: application/json
curl -s -o /dev/null -w '%{http_code}\n' https://perritodeck.dev/nope        # 404
curl -s https://perritodeck.dev/nope | grep -c 'This page ran off'           # 1: it's the site's 404 page
curl -s -o /dev/null -w '%{http_code}\n' https://perritodeck.dev/README.md   # 404
```

With a Pages project, its `*.pages.dev` address answers 301 to the bare domain like `www`
does. Then in a browser, `/`, `/download` and `/plugins/` show no CSP errors in the console
(the demo deck ticks, your system's card is highlighted, the search box filters), and
`https://perritodeck.dev/img/og.png` loads. A link to the site pasted into a chat app shows
that picture with the page's title.

The privacy policy describes current behaviour (pairing secret, host certificate, the
firewall note); keep it in step with what the apps actually do.
